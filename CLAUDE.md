# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Project Overview

Dynamical is a C++20 Vulkan engine with a marching cubes voxel world (GPU meshing), grass looked up in baked rays, glTF models, Jolt physics, and OpenXR VR rendering alongside the desktop window. It uses an ECS architecture powered by EnTT.

The previous 2D tile map simulation (tile rendering, heightmap world, SPH particles, AI) is archived in `archive/tilemap/` (not compiled).

## Build System

Uses CMake with vcpkg for dependency management. Generator is Visual Studio 17 2022.

```bash
git submodule update --init   # FastNoise2, VulkanMemoryAllocator, imgui, implot, tracy

# Configure (vcpkg toolchain is set via CMakePresets.json, needs VCPKG_ROOT)
cmake --preset vcpkg

# Build
cmake --build build --config Debug

# Run from build/ : resources are loaded from ./resources
cd build && ./Debug/dynamical.exe fullscreen=false window_width=1280 window_height=720 vr_mode=1
```

Shaders (`.glsl` in `src/renderer/shaders/`) are compiled to SPIR-V via `glslangValidator --target-env vulkan1.1` (subgroup ops) as part of the CMake build. Resources are copied to the build directory post-build. `-DDYNAMICAL_BUILD_TOOLS=ON` builds `tools/raycast` (grass rays: bake ahead, OBJ of the grass model, comparison with ray tracing).

On NixOS, a `flake.nix` development shell is provided.

## Architecture

### Game Loop (`src/logic/game.h`)
Entry point is `src/main.cpp` → `Game::start()`. The game loop runs: `renderer->prepare()` → `systems->pre_tick(dt)` → `systems->post_tick(dt)` → `renderer->render()`.

### ECS Pattern
- **Registry**: Centralized `entt::registry` (EnTT 3.16) in `Game`. Context variables: `reg.ctx().emplace<T>()` / `reg.ctx().get<T>()` / `reg.ctx().find<T>()`
- **Components** (`src/logic/components/`): Plain data — `Transform`, `ModelRenderable`, `Camera` (desktop), `VRRig` / `VRInput`, `RenderSettings`, `Input`
- **Systems** (`src/logic/systems/`): Inherit from `System` with virtual `tick()`, managed by `SystemSet` (pre/post tick). Simple ones are declared with `DEFINE_SYSTEM` in `system_list.h`

### Rendering (`src/renderer/`)
- **Two render targets, recorded in parallel every frame**: `ClassicRender` (desktop swapchain) and `VRRender` (OpenXR, one swapchain per eye). Each has its own render pass, framebuffers, command buffers and view UBOs
- **Scene passes** (`scene_pass.h`, `passes/`): `TerrainPass` (the ground and its soil patches, docs/ground.md), `GrassPass`, `ModelPass`, `UIPass` (desktop only). Each builds one pipeline per target; `update()` runs on the main thread, `record()` runs concurrently for both targets and must only read shared state (use `const entt::registry&`)
- **Frame sync** (`renderer.cpp`): per-frame fence; transfer → compute → graphics chained with semaphores; one graphics submit holds both targets' command buffers
- **Context** (`context/`): VRContext (OpenXR instance first, it picks the Vulkan extensions and GPU) → Windu (SDL2) → Instance → Device (+ VMA) → Transfer → Compute → Swapchain
- **Conventions**: world is Y up, -Z forward (east +X, north -Z for the sun); projections are Vulkan clip space (Y flipped, depth 0..1); `ViewUBO` is set 0 binding 0 of every scene pipeline, the shade of the plants (`TreeShade`) binding 1, the soil maps of the chunks (`SoilMaps`) binding 2, the lights of the frame (`Lights`) binding 3; `Context::writeViewSet` writes all but the first

### Lighting (`src/logic/sky/`, `src/logic/lighting/`, `src/renderer/lighting/`, docs/lighting.md, docs/lighting/built.md)
- **Sky** (`Sky` context variable, `"Sky"` system with `time` and `day_length` scene variables in every terrain scene): sun and moon from the time of the day (24 minutes a day, stopped in captures), `skyLight()` gives the one directional light, the sky colours and the ambient light; mirrored by `shaders/include/view.glsl` (`skyColor`, `skyRadiance`). `SkyPass` draws the sky first in every renderer. `PointLight` + `Transform` entities are torches (`"Torch"` system, scene `forest_torch`)
- **Scene fragment shaders** include `include/scene.glsl` and end with `writeLit(unlit, sunlit, shade, position, alpha)`; they are compiled twice (`<name>.spv`, and `<name>.rt.spv` with `-DRAY_TRACING`, picked by `sceneFragmentShader()`). `include/*.glsl` are not compiled on their own; `*.rt.*.glsl` only exist with ray tracing
- **Ray tracing** where the GPU has ray queries (`RayContext`, `ctx.device.ray.enabled()`; `ray_tracing=false` forces the fallback, which is the reference of the goldens): `RayScene` builds a structure per chunk (from `ChunkTriangles`, the triangle count read back from the GPU), per mesh the passes give (`RayMeshes`: species of plants with alpha tested leaves, models), per animal near the viewers (`RayAnimals`, skinned by `animal_skin.rt.comp.glsl`, refitted), and the top level structure every frame in the compute commands; the geometry table tells a shader what it hit (`include/rays.glsl`, `traceShadow`)
- **Sun** (`SunVisibility`, one per target): scene passes draw `colour` and `sun` apart (two attachments, `Context::sceneAttachments()`), rays to the sun's disc within the tier's `traced_range` (from the point the depth gives, lifted by `liftAlpha` where a pass pushed its depth under the ground, and brought nearer the eye by what the depth is off by in floats) are filtered over time, `composite.frag.glsl` brings them together; overlay passes (`ScenePass::overlay()`, the UI) draw after
- **Probes** (`ProbeVolume`, `logic/lighting/probes.*`): a brick of 65³ probes per chunk (4 m), L1 light per colour + sun and sky seen, a ray budget a frame (`RenderSettings::probe_rays_per_frame`); `probeLight()` in `include/probes.glsl` is the ambient light of every scene shader, and the sun's shadow beyond the traced range
- **Plant volumes** (`PlantVolumes`): each species baked into 3D textures; far plants are boxes in the rays and are drawn from the volume in place of billboards (`vegetation_volume.*.glsl`)
- Tiers per target in `RenderSettings::lighting` (`lighting=off|low|medium|high`), captures wait for `LightingStats::settled()`. Tests `LIGHT.*` in `tests/unit/lighting.cpp`, shots `tests/capture/lighting*.capture.json`. Not run in VR yet

### Terrain (`src/logic/terrain/`, `src/renderer/terrain/`)
- **Chunks**: 64³ marching cubes of 4 units, density sampled on a 67³ grid (1 sample border) in `[x][z][y]` layout, > 0 is solid
- `ChunkManagerSys` streams chunk entities around the desktop camera and VR rig; `ChunkGeneratorSys` fills `ChunkVolume` with `TerrainGenerator` (FastNoise2) on the taskflow executor
- `TerrainSys` (post tick) records the marching cubes compute shader into the compute command buffer; meshes stay on the GPU (vertex buffer + indirect draw per chunk slot, slots recycled after `NUM_FRAMES + 1` frames)
- `TerrainVertex` (32 bytes): position, octahedral normal (decoded in `terrain.vert.glsl`, `grass.vert.glsl`, which interpolate it to their fragment shaders) = the sum of the normals of the triangles around the vertex, weighted by their areas, from the four cubes around its edge (`vertexNormal` in `marchingcubes.comp.glsl`, `MarchingCubes::vertexNormal`, tests `TERRAIN.*` in `tests/unit/terrain_normals.cpp`; every copy of a vertex gets the same, across chunks too), `curve` = second derivatives of the ground height (xx, xz, zz) from the second differences of the density (`groundCurve`, `logic/terrain/ground_curve.h`, mirrored in `marchingcubes.comp.glsl`)

### Ground (`src/logic/terrain/soil.*`, `src/renderer/terrain/soil_maps.*`, `passes/terrain_pass.cpp`, docs/ground.md)
- **Soil maps** (`SoilField`, in `dynamical_sim`): patches of mud, stones and sand, one Perlin fractal each, anchored to the world; `cover` is the part of the ground a kind takes (the threshold is measured). Baked per chunk in a 67² RGBA map on the terrain vertices plus a border of one: RGB how far into a patch of each kind (0.5 on the edge, `edge_width` 8 m from 0 to 1: the noise over its slope, a distance), A the height of the grass next to the patches
- `SoilMaps` (renderer, always there) bakes and uploads them (a layer of a 2D array per chunk slot through `ChunkLayers`, which `GrassPass` uses for its height maps too), set 0 binding 2; passes get a chunk's layer from the `SoilLayers` context variable and push it per draw
- **Textures** in `resources/ground/` (generated, git ignored): `tools/ground_import.py --source <Tautavel> --lfs <lfs objects>` writes mud, stones, sand, rock and earth (albedo, and normal + height + occlusion) from the Unity project's terrain textures. Flat colours and the old rock without them
- `terrain.frag.glsl`: layers are not faded, the one whose texture stands higher shows (stones come out by their tops, mud fills the hollows, earth stays on the ledges of the rock); the map is read a few metres off (`soilWarp`, the same in `grass.frag.glsl`) so that edges wind; rock on the two vertical planes of the steep faces, the higher of the two where they meet; stones at the foot of the rock (`RenderSettings::scree`); larger tiles far away
- No grass on the patches: the shell gets shorter towards them (`grass.vert.glsl`, the map's alpha), blades are dropped one by one over the edge by their id (`grass.frag.glsl`). Tests `SOIL.*` in `tests/unit/soil.cpp`
- **Relief** (docs/ground-relief.md, `logic/terrain/ground_relief.{h,cpp}`): the height maps of the mud, the stones and the sand are built as tiles of triangles and the rays of the grass baked on them (`bakeGrassModel`; `resources/ground_relief_<name>.bin`). `reliefAt` in `terrain.frag.glsl` looks the view ray up and `soilLayer` reads the textures where it meets the relief (set 1 bindings 3 and 4, depths in `terrain_pass.cpp`, `RenderSettings::relief`, `ground_relief=0` flat). Tests `RELIEF.*` in `tests/unit/ground_relief.cpp`

### Grass (`src/logic/grass/`, `passes/grass_pass.cpp`, docs/grass.md)
- No blade geometry: `GrassPass` draws the chunks again as a shell at the top of the grass; `grass.frag.glsl` looks each view ray up in rays baked against a generated tile of blades repeated to infinity (`GrassTracer`)
- Baked (`bakeGrass`, in `dynamical_sim`): oblique rays at 4 elevations, each with its own number of azimuths (`GrassBakeParams::angles`: the lowest rays, 9.5° from the top of the grass to its middle over 3 tiles, then 22.5°, 45°, 67.5°), and a 2D texture of rays from the top; RGBA8 = hit height (part of the way left for the lowest rays), octahedral normal, blade id. An oblique ray is stored where it crosses the **middle** of the grass; the view ray is looked up where it crosses the middle too, in the two elevations around its own, blended along their reach (docs/grass/12-elevations.md)
- The oblique rays are a 2D array (a layer per azimuth of each elevation, layout in specialization constants), not a 3D image: GPUs do not filter those anisotropically. Sampler trilinear + 16× anisotropy, `textureGrad` with the footprint of the pixel on the ground; the shader blends the two nearest azimuths (`azimuth_dither`: towards one view per pixel)
- Tile space is sheared around the ground by the lean of the blades (wind, terrain normal): roots do not move
- Several layers (up to 4, the kinds of plants of the place, see Species) of tiles at different sizes, heights and noise warps, closest hit wins; patches, blade colours, curved blades, blade shadows: one doc per feature in docs/grass/ (plan.md first)
- **Height map** (docs/grass/11-height-map.md, 15-species.md): a 65² map per chunk on the terrain vertices holds the top of the plants of each place (`GrassTopField` in `grass_species.{h,cpp}`: the tallest of the kinds that grow there, each as tall as its own height noise says, the highest within 2 m of the vertex). `GrassPass::update` bakes and uploads it (one layer of a 2D array per chunk slot, `Transfer::updateImage`) when the chunk gets its mesh, again when the species, `patch_amount` or `height_map` change; `grass.vert.glsl` reads it (chunk origin and layer pushed per draw) and gives `v_cover` (slope and soil) apart. `GrassHeightField` (`grass_height.{h,cpp}`, FastNoise2 octaves, 0.55 to 1 m) is the height of the meadow without the species (`species.size` 0) and the sandbox's grass
- **Seen through on crests** (docs/grass/13-see-through.md): where the ground bends down along the view the ray comes out of the grass again; what the lookup met deeper than `sink² / (2 falling)` is discarded (`RenderSettings::Grass::silhouette`, `grassSeeThrough` on the CPU), only on the pixels where the back of the shell is in front of the ground: `GrassPass` draws the shell three times, its back faces mark the stencil (`grass_back.frag.glsl`), its front faces are whole where it is 0 and cut where it is 1 (elsewhere the ray ends on the ground of the hill, and the cut left bands of dark earth under the crests). The scene render passes have a stencil for it (`Context::sceneDepthFormat`). `falling` comes from the terrain vertices' `curve`
- `TerrainPass` darkens the terrain and pushes its depth back under the grass (`RenderSettings::grass_pass`): the grass hits may be a little under the real ground. Seen along the ground it draws it as grass seen from the side
- **Slopes**: the grass stops blade by blade where the ground gets steep (`slopeGrass` in `grass.frag.glsl` and `terrain.frag.glsl`: the normal of the pixel from 0.8 to 0.71, wound by a noise; a threshold on the normal followed the triangles of the terrain) and gets shorter before that, per pixel on the same wound normal (`slopeTall`: whole at 0.88, a quarter at 0.74); the shell lowers with it, the same curve 0.08 further up the slope per vertex so that it stays over the grass, down to the ground at 0.62 (`grass.vert.glsl`)
- **Plants** (docs/grass/13-plants.md): `GrassModelParams::kind` (`GrassKind`) picks the tile the rays are baked on: the meadow of the engine, and nine more made of ribbons, tubes, spindles and leaflets (fescue, cocksfoot, ryegrass, timothy, oat, clover, clover in flower, plantain, dandelion), modelled in metres (`GrassModel::tile_size`, `height`). `raycast --gallery`, `--kind`, `--metres`. Test `GRASS.11`
- **Species** (docs/grass/15-species.md, `grass_species.{h,cpp}`): every kind has two octaved Perlin noises (channels of a repeating texture read at two sets of scales, set 1 binding 10): how much of it, and how tall it grows (`1 - patch_amount` to 1 of its modelled height). The four kinds with the best first noises are the layers (`species()` in `grass.frag.glsl`, `grassSpeciesAt` on the CPU, the same constants in both), each with a density (`keep`, by `species.overlap`, in the high bits of the `layers` push constant) under which a layer drops the plants whose id is over it (`hitPlant`); a kind fades out before the fifth takes its place (`fade`), its last plants are small (`stunted`), a layer without a kind is the first kind again. Small kinds (`GrassKindInfo::small`) get `species.shade` less of their noise where the tall kinds of the place grow tall, more where they stay short. No undergrowth layer any more. Plant ids are ranks in a best-candidate order of the tile (`tileSites`, `GrassModel::ids`): any first part of the plants is spread evenly, `grassSpeciesAt` mirrors it. The rays of the ten kinds are in the same array images (204 layers a kind, 192² tiles, 252 MB), one `resources/grass_raycast_<kind>.bin` each; kind sizes are specialization constants. `grass_kind=clover`: one kind everywhere. Tests `GRASS.13`, `GRASS.14`, `GRASS.15` (`tests/unit/grass_textures.cpp`)
- **Colour map** (docs/grass/14-colour-map.md): the rays bake the colour of what they meet too (`GrassModel::colours` from the part of each vertex: green by the height, flowers and seeds of the kind), in a texture of its own next to height, normal and id (`GrassRaycast::oblique_colour`, `top_colour`, `makeGrassColour`: RGBA8 or BC1, sRGB, set 1 bindings 8 and 9), read once for the closest hit. `RenderSettings::Grass::baked_colour` 0: green by the height alone. Test `GRASS.12`
- `dynamical` bakes `resources/grass_raycast_<kind>.bin` in the run directory when it is missing or its key is stale (never committed). `lookupGrass` mirrors the shader on the CPU (tests `GRASS.*` in `tests/unit/grass.cpp`, `raycast --preview`)

### Physics (`src/physics/`)
- Jolt 5.5, fixed 60 Hz step (`PhysicsSys`, pre tick after gameplay systems), `Transform`s of dynamic bodies interpolated between the last two steps
- Entities get a body by adding `RigidBody` (box or sphere, dynamic / kinematic / static) next to a `Transform`; destroying the entity or removing the component removes the body. Kinematic bodies follow their `Transform` (VR hands)
- **Terrain colliders** (`terrain_colliders.cpp`): the world is cut in cells of 16³ marching cubes; cells overlapping a body's swept bounds this frame are meshed on the CPU (`logic/terrain/marching_cubes.cpp`, shared vertices so Jolt can detect internal edges) and added as static `MeshShape` bodies before the step, in sorted order; cells on the predicted path (1 s) are prefetched on taskflow; idle cells are evicted after 5 s of simulation. Densities come from the loaded chunk volume or straight from `TerrainGenerator::sample`, so collision works without rendering or streaming
- Dynamic bodies use `LinearCast` motion quality and enhanced internal edge removal

### Kinematic walk (`src/logic/agents/`, docs/physical-agents/ik-gait.md)
- Scenes `ik_walk_slope` (tilted plane) and `ik_walk_terrain`; headless `ik_check`, `ik_check_terrain`. Tests `IK.*` and `GAIT.*` in `tests/unit/ik_gait.cpp`
- `RigPose` (joint angles) is written by `GaitBase` (procedural gait), corrected by `Fabrik`, applied by `RigPoseApply` (`MoveKinematic`)
- **IK is component driven**: any system posts `IKTarget` entities for an `IKChain`; `Fabrik` solves them all in one batch (FABRIK, pole, joint limits). `GaitFootIK` owns the leg targets, `GaitBalance` places the pelvis through `solveChain()`
- `GroundField` (plane or marching cubes surface from the density samples) is what feet are planted on, no collider
- **Scrambling** (`GaitParams::scramble`, scene variable `scramble`, off by default): from 20° to 50° of slope the trunk comes down toward the ground, and `GaitHandIK` (between `GaitFootIK` and `GaitBalance`) lays the palm of a hand within reach flat on it, on prints fixed in the world; `GaitBalance` leans the trunk for the hands' reach and moves the centre of mass toward the planted palms. Tests GAIT.12 to 14
- **Terrain walker** (docs/physical-agents/reports/terrain-walker.md): `walker_terrain_train` trains the physical walker on the marching cubes terrain (`WorldTerrain` colliders, `GroundTerrain` field). `WalkRoutes` draws spawn points and target directions where the ground stays within 20° up, 7° down and 12° across; heights (fall test, head error, stats) are measured from the ground under the walker. `GaitRoutes` records the kinematic walk as GAIL demonstrations (`walker_demo_gait`, `walker_demo_terrain`; 1.36 m/s, limits hold). Tests `TW.*` in `tests/unit/terrain_walker.cpp`; `tools/terrain_eval.py` evaluates by slope band
- A planted foot comes before a joint limit (`GaitParams::yield_limits`): the walk covers any slope, realistic up to about 20°. The body files' ankle swing limits are wider than Unity's export (`unity_y_deg`, `unity_z_deg` keep the originals)

### Forests (`src/logic/vegetation/forest.*`, `src/renderer/tree_shade.*`, `src/view/camera_walk.*`, docs/forest.md)
- Scenes `forest` (free camera, VR) and `forest_walk` (the camera walks through a forest; `tools/forest_video.py` makes the MP4). Tests `FOREST.*` in `tests/unit/forest.cpp`
- `ForestField` (context variable, `std::shared_ptr`): cover 0..1 from patch noise times a mask on the slope of the heightfield (no forest over `max_slope`), and a stand (kind of forest); defined on an 8 m lattice anchored to the world
- `resources/forest/tautavel.forest.json`: stands (pines, oaks, alders and birches) and `everywhere` layers. A layer is a world-anchored jittered grid (`spacing`) kept by `fill` times a function of the cover (`forest`, `edge`, `open`, `all`), optionally in clumps
- `ForestSys` (`"Forest"`) puts each chunk's candidates on its ground (`ChunkForest`, destroyed with the chunk); plants do not depend on the chunk load order. Species are preloaded through `VegetationPreload`
- `TreeShade` (renderer, always there): crown shadows splatted on a 2048 m wrapping map from the `Plant` signals, set 0 binding 1; `treeShade()` in the terrain, grass and vegetation fragment shaders. `ViewUBO::tree_shade` carries the strength (`RenderSettings::tree_shade`)
- `CameraWalk`: picks a line (open, forest, open, gentle ground), routes around trunks and low branches on a grid (Dijkstra), walks the camera. Captures wait for `VegetationStats::species_loading == 0`, sequences keep their pace after a late frame
- **Walk over the land** (docs/tautavel-walk.md): scene `tautavel_walk` = forests, herds, soil patches and their relief, grass species, with a `CameraWalk` whose `lead` (open land at each end), `soil` and `herds` parameters (off in `forest_walk`) pick the line for the soil it crosses and the herds along it, and turn the camera to them. `tools/forest_video.py --scene tautavel_walk`

### Action agents and the sandbox (`src/logic/sandbox/`, docs/action-agents.md)
- Animals that decide what to do, to survive and reproduce; deer (`deer_red`) and wolves (`wolf_2`) first, policies per species, all learning in one world. An animal is a ragdoll (`AnimalBot` as a component) with **two agents**: its walker (`Animal_<id>`, 30 Hz, the joints) and its mind (`Action_<id>`, 5 Hz: speed, turn, head yaw and pitch, a mode among Move, Feed, Attack, Mate, Rest). Decisions and what was decided while building: the two tables at the top of the doc
- **Several agents in a world**: `AgentIO` (`logic/agents/agent_io.h`) is the one agent of a world (context variable) or a **component** (every entity with one is an agent): `branches` / `discrete` (hybrid actions), `sensors` (more vectors, buffers of rows), `requested` (asks for a decision; the host clears it), `id` (given by the host). `AgentsReset` context flag for the trainer's RESET. `WorldsEnvironment` (`src/train/worlds_env.cpp`) gathers agents by behaviour at every exchange, sends a behaviour's brain parameters with its first agent, steps until an agent asks or ends. Fixture: scenes `pursuit`, `pursuit_eval` (`logic/agents/pursuit.{h,cpp}`), `tools/train_sphere.py --scene pursuit`
- **Orders** (`animal_agent.h`): `AnimalMode`, the head offsets, a second sensor of the walker `nogail_order` (hidden from GAIL by the fork), `rateAnimal` (command, head and mode rewards), `AnimalSpawn.orders` for the animal alone (scenes `animal_orders_train`, `animal_orders_eval`, `training/animal_orders_ppo.yaml`, `ranges/sandbox.json`). The walker's steps are free functions for any `AnimalBot` (`buildAnimalRagdoll`, `standAnimalBot`, `driveAnimalBot`, `syncAnimalBot`); ragdolls take a collision group and `PhysicsLayers::animal_layer` (collide with each other)
- **Rules of life** (`life.{h,cpp}`, `resources/agents/params/life.params.json`, `life_hunters.params.json` with men and their spear): energy (basal + positive mechanical work), health, wounds from the contact impulse of a head in Attack mode (`SandboxSys::Contacts`), grazing with the muzzle in a `GrassField` that is eaten and grows back, carcasses, mating, gestation, young born at 0.6 of the body (`scaleAnimalBody`) that grow, old age, respawn under a minimum. A fall ends the walker's episode, not the life. `lifeScale`, `walkerShare`, `rewardScale` are environment parameters
- **Rewards**: objective in the engine (birth +1 each parent, early death -1); intermediate terms in `resources/agents/rewards/<id>.rewards.json` as expressions (`expr.{h,cpp}`) over `SandboxSignal`s (`TrainingEnv.exe mode=signals`), rewritten by the LLM between rounds from `<run>.round.json`. `tools/sandbox_round.py --name <n> --round <k> --steps <s> [--puppet]` (config from `training/sandbox_ppo.yaml`, each round from the last)
- Systems `Sandbox`, `SandboxLife`, `SandboxObserve@observe` (template `common/sandbox_world.json`); scenes `sandbox_train`, `sandbox_puppet` (kinematic bodies slid along their commands, minds only: a check, not the product), `sandbox_heuristic` (scripted minds), `sandbox_eval` (`mode=eval`: summary and a replay for `tools/sandbox_video.py`), `sandbox_view` (shapes in the viewer)
- **Inference** (`src/onnx/agent_policy.{h,cpp}`): `AgentPolicy` (any exported layout), world system `Policies` (per behaviour, from a run's folder), `makePolicyHandle` for the single animal with orders
- Tests `EXPR.*`, `LIFE.*`, `SANDBOX.*` (`tests/unit/sandbox.cpp`, skipped without the deer's and the wolf's bodies), `PURSUIT.*`, `MA.*` (`tests/protocol/multi_env.cpp`), `AP.*` (`tests/onnx/agent_policy.cpp`)

### Models (`src/renderer/model/`)
- glTF 2.0 through tinygltf (`gltf_loader.cpp`), flattened into one vertex/index buffer with node transforms baked in. `ModelManager` (context variable) caches files; instances are entities with `Transform` + `ModelRenderable`

### VR
- `vr_mode` setting: 0 desktop only, 1 VR alongside the desktop when an OpenXR headset is found (falls back silently otherwise)
- `VRActions` (renderer side) writes controller and head poses to the `VRInput` context variable; `VRControlSys` does locomotion (left stick), turning (right stick), throws boxes with the right trigger (hand velocity), and drives the kinematic hand bodies

### Physical players (`src/logic/player/`, `src/view/player_input.*`, docs/players.md)
- Unity Dynamical's `GenericPlayer`, `FPSPlayer`, `VRPlayer`, `Hand`, `Grabber`, `Thrower` ported; scenes `player_fps` (WASD, mouse, E picks up, click throws), `player_vr`, `player_horse`, `player_deer`. The other scenes keep `PlayerControl` and `VRControl`
- **Input** (`generic_input.{h,cpp}`): Unity's `GenericPlayerInput` interface (`getMovementAxis`, `getViewAxis`, `getJumpButton`, `getRunButton`, ... `isActive`) implemented by the components `MouseKeyboardInput` (WASD as physical keys, mouse), `ControllersInput` (SDL gamepad), `VRPlayerInput` (the headset's controllers; `VRInput` stays the renderer's raw state) and `ScriptedInput` (tests). Each holds its device's state, written by the system of the same name (the first two in the viewer); systems ask `playerInput(reg, entity)` (the scripted one, else the active device used last) and call the functions, there is no input struct. Presses are tracked by who needs them (`Holder::was_interact`, `Rider::was_jump`)
- A player is an entity with a dynamic `RigidBody` at its eyes (capsule, `lock_rotation`); one system per component, systems only meet through components: `PlayerView` (← `LookTurn`, `VRBody`), `PlayerLegs` (stand / walk / jump forces), `VRTracking`, `VRBody` (body follows the head, turn, pose hold without focus), `Hand` (← `VRHands`), `Grabber` (← `Grab`: fixed constraint on what the hand touches, throw), `Holder` (← `Hold`: FPS pick up), `BodyDrive` (← `BodyDrives`: Jolt `SixDOFConstraint` with force-limited velocity motors; hands and held bodies are both this), `DesktopView` (← `PlayerViewpoint`, after `Physics`: writes `Camera` and `VRRig`). `makeFPSPlayer`, `makeVRPlayer`, `PlayerSpawn`
- **`FixedSteps`** (context variable, `physics/physics_sys.h`): what host systems do at the physics rate; `Physics` calls the steps around each 60 Hz Jolt step in the order the systems registered. `TerrainNeeds`: boxes that need terrain colliders without a body in them (under the legs). `RigidBodySys` puts the entity in the Jolt body's user data (`bodyEntity`)
- **Riding** (`mount.{h,cpp}`, `logic/animals/steer.{h,cpp}`; scenes `player_horse`: forests, herds, horses at the spawn, and `player_deer`: the physical red deer with its policy on a flat ground; `third_person=<m>` puts the camera behind): `Mountables` gives the animals of the species listed a `Mountable` (saddle = top of the skin of the back between the hips, carried by its joint; a kinematic collider box while a `Rider` is within range), `Mounting` (jump against an animal gets on: legs limp, `AnimalSteer` on the animal; jump gets off), `MountSteering` (walk axis along the view's yaw = heading, walk or run speed), `RiderSeat` (the body is held over the saddle by a capped, eased spring force at the physics rate: no jump in its acceleration). `AnimalSteer` (heading, speed, run) is all the animal knows: `SteeredWalk` walks kinematic animals (`stepWalker`, idle / walk / run clip, `AnimalGait`), `HerdSys` lets go of a steered member and takes it back; `AnimalBotSteer` makes an `AnimalBotProxy` (Transform + `AnimalPose` from the ragdoll's segments) per world with an `AnimalBot` and turns the proxy's `AnimalSteer` into the bot's `WalkCommand` within its trained ranges. `AnimalSkin` marks an `Animal` that is only a ragdoll's drawn skin (`AnimalAgentView`). `MountSpawn`: animals standing at the spawn. `tools/ride_video.py --ride horse|deer`
- Collision groups per player (`PlayerCollision`): body / hands / held bodies / the animal ridden. Tests `PLAYER.*` in `tests/unit/player.cpp` (flat ground, scripted input and tracking), `MOUNT.*` in `tests/unit/mount.cpp`, `HERD.2`. Not run in a headset, nor with a gamepad yet

### Profiling (`src/util/profile.h`, `src/renderer/context/gpu_profile.*`, docs/profiling.md)
- Tracy (`lib/tracy`, `-DDYNAMICAL_PROFILE=OFF` leaves it out), started by hand (`TRACY_MANUAL_LIFETIME`): `profile=true` on `dynamical` and `dynamical_train` calls `profile::start()` in main, events are kept from there until a Tracy profiler connects (this machine only, `TRACY_ONLY_LOCALHOST`). Without it no thread, no socket, a zone is one branch; the tests and the tools never start it
- **CPU**: `SystemSet` opens a zone around every call of every system, named as the scene names it (`preinit <name>`, `init <name>`, `finish <name>` too); `DY_ZONE()`, `DY_ZONE_N("literal")`, `DY_ZONE_DYNAMIC(const char*)`, `DY_PLOT`, `DY_FRAME()` (end of the main loop; a `ScenarioRunner::step` without a window), `DY_FRAME_NAMED("Headset")`. Workers of an executor are named with `profile::namedWorkers()` (`util/profile_workers.h`)
- **GPU**: `GpuProfile` (`Context::gpu_profile`) makes the Tracy Vulkan context (calibrated timestamps where the GPU has them, one context: the queues are the same one). `DY_GPU_ZONE(ctx.gpu_profile, command, "name")` in the compute commands (marching cubes, ray scene, probes, plant volumes, animal skinning) and in both targets' command buffers (`<pass> (desktop)`, `<pass> (headset)`, sun rays, composite; names from `PassZones`). A GPU zone ends before its command buffer does, and that buffer is submitted; `collect()` once a frame at the start of a target's buffer
- `tools/profile_run.py --name <n> -- <engine arguments>`: runs with `profile=true`, records with `tracy-capture`, writes `build/profiles/<n>/` (`summary.txt`, `zones.csv`, `zones_self.csv`, `gpu.csv`, `frames.csv`, `trace.tracy`): the text to read when the question is where the time goes. Builds `tracy-capture` and `tracy-csvexport` in `build/tracy_tools` the first time. `gpu_times=true` (pass means in the log) is still there. Headset zones not run
- The profile of reference is the walk: `--between "CameraWalk : started" "CameraWalk : finished" --frame-set Walk -- scene=tautavel_walk var.exit=true gpu_times=true ...` (docs/profiling.md). `CameraWalk` posts those two messages (`profile::message`), marks its frames (`Walk`) and ends the process with its `exit` parameter (scene variable `exit`); `--between` cuts the tables to what lies between two messages

### Configuration
- Settings serialized to `./config.7.json` via Cereal (JSON), overridable with `key=value` arguments
- **Graphics levels** (docs/graphics.md, `logic/settings/graphics.{h,cpp}`): `resources/graphics.json` holds `ultralow`, `low`, `medium`, `high`, `ultrahigh`, each a value for what a frame costs (view distance, ray tracing on or off, the lighting of each target, probe rays, far plants, anisotropy, relief, grass layers / shadows / see through, LOD bias, streaming budgets a frame). `graphics=<name>` or `"graphics"` in the config (`high`), the `Graphics` list of the debug menu while running (`ray_tracing` and `RenderSettings::textures` are read at the start); `Game` reads the file into the `Graphics` context variable, `Renderer` applies it to the `RenderSettings` before the command line's own keys. Captures and probes use the defaults of the code unless `graphics=` is given, and `high` repeats those defaults (tests `GRAPHICS.*` in `tests/unit/graphics.cpp`): a default changed in `RenderSettings` changes in `high` too. The other four levels are not measured

### Reference docs (`docs/reference/`)
- One page per registered system, render pass and registry-touching service (`systems/`), per component and context variable (`components/`: every system that touches it, read / write / readwrite, side effects), per folder of `src/` (`folders/`). ## Code Conventions

- C++20 standard
- Profiler zones: `DY_ZONE()`, `DY_ZONE_N("name")`, `DY_GPU_ZONE(ctx.gpu_profile, command, "name")` (see Profiling); a system needs none at the top of its `tick`, `SystemSet` opens it

- Taskflow executor (context variable) for chunk generation and parallel command recording
